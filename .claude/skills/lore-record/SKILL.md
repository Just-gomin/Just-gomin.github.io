# lore 기록

이번 작업에서 정한 것을 다음 사람이 이유까지 알 수 있게 `docs/`에 남깁니다. 초안은 PR에서 사람이 승인합니다.

## 1. 기록할 것 찾기

세션을 돌아보며 아래에 해당하는 것을 찾습니다.

- **결정**: 둘 이상의 방법 중 하나를 고른 것, 기존 결정과 다르게 한 것, 설계 승인에서 정한 값과 그 이유
- **사고**: 장애나 버그로 사용자나 운영에 영향이 간 일

다음은 기록하지 않습니다.

- 코드만 읽어도 알 수 있는 구현 세부
- 따로 고르지 않고 기존 관례를 따른 것
- 이번 작업과 상관없는 것

찾은 것이 없으면 기록을 만들지 않고, 사람에게 "새로 정한 것이 없습니다"라고 알립니다.

## 2. 기존 기록 확인

설계 단계에서 이미 확인했으면 건너뜁니다. 아니면 고친 파일마다 얽힌 결정을 봅니다.

```sh
lore why services/payment/retry/queue.ts
```

새 결정이 기존 결정과 충돌하면 기존 기록을 고치지 않고, 새 결정이 기존 결정을 대체하게 합니다.

## 3. 초안 만들기

```sh
lore add decision --slug retry-5 --title "재시도를 최대 5회로 늘린다" --specs payment-retry --supersedes ADR-20261105-retry-queue
lore add incident --slug duplicate-charge --title "재시도 중 중복 결제 발생" --specs payment-retry --decisions ADR-20261022-idempotency-key
```

- `--slug`는 영문 소문자, 숫자, `-`로 내용을 짧은 몇 단어로 줄인 것입니다.
- `--specs`에는 결정이나 사고가 걸친 스펙 ID를 쉼표로 이어 적습니다.
- `--sources`에는 근거가 된 소스 노트 ID나 이미 있는 PR, 이슈 링크를 적습니다. 근거가 세션 안의 대화뿐이면 비워 둡니다.
- 사람이 밝힌 이유가 그대로 있으면 `--confidence stated`를 붙입니다. 다른 에이전트를 거쳐 전달받은 말도 사람의 말이 그대로 인용되어 있으면 같습니다. 이유를 짐작했으면 기본값 `inferred`로 둡니다.
- `status`는 기본값 `accepted`입니다. 설계 승인을 받은 결정이기 때문입니다. 승인 없이 제안만 하는 결정이면 `--status proposed`를 붙입니다.
- 출력의 `path`가 만든 파일입니다. 본문은 비어 있으니 다음 절대로 채웁니다.

## 4. 본문 채우기

결정 기록은 그 문서만 읽어도 이유를 알 수 있게 씁니다.

- **배경**: 왜 이 결정이 필요했는지
- **결정**: 무엇을 골랐고 왜 그것인지
- **검토한 대안**: 실제로 견준 방법과 고르지 않은 이유
- **결과와 감수한 비용**: 이 결정으로 생기는 제약과 비용

사고 기록은 "무슨 일이 있었나", "원인", "조치"를 채웁니다.

지킬 것은 다음과 같습니다.

- 세션에 근거가 없는 이유는 지어내지 않습니다. "이유 불명"이라고 적고 `confidence: inferred`를 그대로 둡니다.
- 검토하지 않은 대안을 검토한 것처럼 적지 않습니다. 실제로 견준 것이 원래 동작을 유지하는 것뿐이면 그것을 적고, 견준 것이 없으면 "검토한 대안 없음"이라고 적습니다. 나중에 나온 비교라면 그렇다고 밝힙니다.
- 민감 등급 출처의 구체적인 내용(이름, 금액, 계약 조건)은 옮기지 않고 이유를 일반화해 적습니다.

## 5. 마무리

- `--supersedes`를 썼다면 출력의 `specs_to_review`에 나온 스펙의 본문을 지금 동작에 맞게 고칩니다.
- 동작이 바뀐 스펙의 본문도 고칩니다. "아직 동작하지 않는 것"에 있던 항목이 이제 동작하면 "지금 동작"으로 옮깁니다. 이유를 길게 쓰는 대신 결정 ID를 본문에서 가리켜도 됩니다. 머리말의 관계가 아니라서 "관계는 가리키는 쪽에만" 규칙과 부딪히지 않습니다.
- `lore build`로 `docs/INDEX.md`를 다시 만듭니다. 이번 작업과 상관없는 줄이 함께 바뀌어도 인덱스는 생성물이므로 그대로 PR에 넣습니다.
- PR 설명에 추가한 기록의 ID를 적습니다.
