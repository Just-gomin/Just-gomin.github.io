## 배경

`/notes`의 태그 필터는 태그를 나열만 하고, 태그 버튼과 CLEAR 버튼에 동작이 없었습니다. 필터를 동작시키려면 두 가지를 정해야 했습니다. 선택한 태그를 어디에 둘지, 그리고 태그를 여러 개 골랐을 때 노트를 어떻게 거를지입니다. 블로그는 정적 내보내기(`output: "export"`)로 배포하므로 서버가 요청마다 페이지를 만들 수 없습니다.

## 결정

선택한 태그는 URL 쿼리 문자열 `?tags=a,b`에 둡니다. 태그는 여러 개 고를 수 있고, 고른 태그 중 하나라도 가진 노트를 보여 줍니다(OR). 선택한 태그 버튼은 `[*]`, 고르지 않은 버튼은 `[ ]`로 표시해 내비게이션과 모양을 맞추고, CLEAR는 쿼리를 지웁니다.

이유는 다음과 같습니다.

- URL 쿼리: 필터를 건 목록을 링크로 공유하거나 북마크할 수 있고, 뒤로 가기가 자연스럽게 동작합니다. 정적 내보내기라도 쿼리 문자열은 클라이언트에서 읽을 수 있습니다.
- OR: 태그가 아직 적어 AND로 거르면 결과가 쉽게 비고, 관심 주제를 넓혀 보는 용도에 OR가 맞습니다.

이 이유는 레포 주인이 선택을 맡긴 어시스턴트 팀이 제시했고, 레포 주인이 진행을 승인했습니다. 레포 주인이 직접 밝힌 말이 아니라서 `confidence: inferred`로 둡니다.

## 검토한 대안

- React 상태로만 두기: 새로고침하면 선택이 사라지고 필터를 건 목록을 공유할 수 없어 고르지 않았습니다.
- 태그마다 정적 페이지 `/notes/tags/[tag]` 만들기: 페이지가 태그 수만큼 늘고 한 번에 태그 하나만 볼 수 있어 고르지 않았습니다.

## 결과와 감수한 비용

- 쿼리는 빌드 때 알 수 없으므로 미리 렌더링한 `/notes` HTML에는 필터 없는 전체 목록이 들어갑니다. 쿼리가 있는 주소로 들어오면 자바스크립트가 로드된 뒤에 목록이 걸러집니다. 자바스크립트가 없으면 필터 버튼은 비활성화된 채로 보입니다.
- `useSearchParams`를 쓰는 컴포넌트를 `<Suspense>`로 감싸야 정적 내보내기 빌드가 통과합니다.
- 태그 목록을 쉼표로 잇기 때문에 쉼표가 들어간 태그는 쓸 수 없습니다.
- 목록을 클라이언트 컴포넌트에서 거르므로 노트 메타데이터가 페이지에 함께 실립니다. 본문은 빼고 넘깁니다.
