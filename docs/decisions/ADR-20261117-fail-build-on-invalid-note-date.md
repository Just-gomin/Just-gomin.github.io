## 배경

`features/note/lib/notes.ts`의 `getNoteMeta`는 `meta.json`의 `date`가 유효한 날짜가 아니면 콘솔에 오류만 남기고 계속 진행했습니다. 블로그는 정적 내보내기로 배포하므로, 이 경우 날짜가 잘못된 노트가 그대로 배포되고 날짜순으로 정렬하는 노트 목록이 깨질 수 있습니다. 콘솔 오류는 빌드 로그에 묻혀 알아차리기 어렵습니다.

## 결정

`date`가 유효한 날짜가 아니면 slug와 잘못된 값을 담은 `Error`를 던져 정적 빌드를 실패시킵니다. 날짜가 잘못된 노트가 배포되어 목록 정렬이 깨지는 것보다 빌드가 실패해 바로 알아차리는 편이 낫기 때문입니다.

이 이유는 레포 주인이 선택을 맡긴 어시스턴트 팀이 제시했고, 레포 주인이 설계를 승인했습니다. 레포 주인이 직접 밝힌 말이 아니라서 `confidence: inferred`로 둡니다.

## 검토한 대안

- 콘솔에 오류만 남기고 계속 진행하는 원래 동작을 유지하는 방법. 오류가 빌드 로그에 묻혀 잘못된 노트가 배포될 수 있어 고르지 않았습니다.

## 결과와 감수한 비용

- 노트 한 편의 날짜만 잘못되어도 전체 빌드와 배포가 멈춥니다. 고칠 때까지 다른 노트도 배포되지 않습니다.
