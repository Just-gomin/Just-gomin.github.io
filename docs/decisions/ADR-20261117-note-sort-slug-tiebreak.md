## 배경

`features/note/lib/notes.ts`의 `getAllNotes`는 노트를 날짜 내림차순으로만 정렬했습니다. 날짜가 같은 노트는 `readdirSync`가 폴더를 돌려준 순서를 그대로 따랐고, 이 순서는 운영체제와 파일 시스템에 따라 다릅니다. 그래서 같은 날 쓴 노트의 목록 순서와 정적 빌드 결과가 빌드하는 컴퓨터마다 달라질 수 있었습니다.

## 결정

날짜 내림차순으로 정렬하고, 날짜가 같으면 slug 오름차순으로 정렬합니다. slug 비교는 로케일을 쓰지 않는 UTF-16 코드 단위 비교입니다.

이유는 다음과 같습니다.

- 같은 날 쓴 노트의 순서가 빌드하는 컴퓨터의 파일 시스템에 따라 달라지면 안 됩니다.
- slug는 폴더 이름이라 노트마다 유일하고, 제목과 달리 글을 고쳐도 잘 바뀌지 않습니다.
- 로케일에 기대지 않는 비교라 어디서 빌드해도 같습니다.

이 이유는 레포 주인이 선택을 맡긴 어시스턴트 팀이 제시했고, 레포 주인이 진행을 승인했습니다. 레포 주인이 직접 밝힌 말이 아니라서 `confidence: inferred`로 둡니다.

## 검토한 대안

- 같은 날짜를 제목으로 정렬하는 방법. 제목을 고치면 순서가 바뀌고, 한글 정렬이 로케일에 따라 달라질 수 있어 고르지 않았습니다.
- `meta.json`의 `date`에 시각까지 적게 하는 방법. 기존 노트를 모두 고쳐야 하고, 시각까지 같으면 여전히 순서가 정해지지 않아 고르지 않았습니다.

## 결과와 감수한 비용

- 같은 날 쓴 노트의 순서를 글쓴이가 정할 수 없습니다. 순서를 바꾸려면 slug(폴더 이름)를 바꿔야 하고, 그러면 노트의 URL도 바뀝니다.
- 대문자와 소문자가 섞인 slug는 코드 단위 순서를 따르므로 대문자가 소문자보다 앞에 옵니다.
